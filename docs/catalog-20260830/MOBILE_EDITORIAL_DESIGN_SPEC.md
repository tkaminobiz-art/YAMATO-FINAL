# やまとの家 デジタルカタログ PC/SP編集設計仕様

作成日: 2026-08-30
状態: **設計確定候補／未実装**
対象: `index.html` 冒頭のデジタルカタログ
正本: `パンフレット0723.pdf`、`first-party-evidence.md`、所有する実邸・設備・図面素材

## 1. 結論

- PCとSPは、同じ情報源と操作ロジックを共有する。
- 誌面は共有しない。PCは横長13面、SPは縦長20面として別編集する。
- SPをPCの縮小・一列化・`object-fit: cover`だけで成立させない。
- 住宅、設備、構造、図面は実在素材を使う。生成素材で事実を代替しない。
- Higgsfield等は表紙モーションの中間表現、Adobe Stockは紙・箔・光・影の補助だけに限定する。
- ページ送りは任意。縦スクロールを拘束せず、カタログを飛ばして次セクションへ進める。

## 2. 参照記事から採用する原則

### Wonderline

参照: <https://www.wonderline.cloud/blog/digital-catalog-design>

- 紙・PDFの見開きをそのままWebへ持ち込まない。
- 重要情報を先に、補足情報を後に置く。
- 写真、説明、仕様、次の行動を同じ階層で混在させない。
- スマホでは、縦方向の閲覧順と操作の発見性を優先する。
- 流用するものと、Web用に作り直すものを分ける。

本件では、写真・確認済み事実・シリーズカラーを流用し、ページ割り・トリミング・文字量・表組み・操作を作り直す。

### Studio

参照: <https://studio.design/ja/blog/mobilefirst-design>

- SPをPCの副産物として扱わず、最初から狭い画面の見え方を設計する。
- モバイル画面の中で、写真・情報・操作が一つの体験として成立するようにする。
- PCでは余白や周辺ギャラリーを加えられるが、SPの主役情報は変えない。

## 3. 設計宣言

- アーキタイプ: **和モダン 55% + エディトリアル 45%**
- トレンド: **静寂デザインのみ**
- 配色: 深紅 `#BD1B21` / 生成り `#F4F1EA` / 箔金 `#C9A24B` / 墨 `#241E16`
- 見出し: 明朝体、500以下
- 本文: 読みやすいゴシック体、400
- 余白感: 超ゆったり。ただし1ページ内の意味のない空白は作らない
- アニメーション: 表紙のみリッチ、ページ送りは控えめ
- 目指す感情: **夜のスマホでも、写真で見た仕様と家づくりの確かさを、一枚ずつ静かに確かめられる。**

## 4. 情報構造

### 共通化するもの

- 見出し、本文、注記、仕様値
- 画像の出典とalt
- ページID、章ID、目次ラベル
- CTAのURL
- ページ履歴、現在位置、操作イベント

### PC/SPで分けるもの

- ページ数
- 写真の選択とクロップ
- 写真と文字の掲載順
- 1ページあたりの情報量
- 改行位置
- ページ送りのモーション
- 目次UI

実装は「共通コンテンツマニフェスト＋PC/SP別テンプレート」とする。同じ文章をHTMLへ二重に手入力しない。

| 横向きタブレット | 821px以上 | PC誌面、左右余白を縮小 |

## 7. SP誌面グリッド

### アートボード

- 外枠: `100svh`内にヘッダー、誌面、操作列を収める
- 誌面: 幅 `calc(100vw - 18px)` を上限とする
- セーフエリア: 上24px、左右20px、下24px
- 本文幅: 19–25字程度
- 1面の本文: 90字を上限。超える場合はページを分ける

### 基本テンプレート

1. **Photo Lead**: 写真65–72%＋文章28–35%
2. **Chapter Door**: 和紙背景＋見出し＋一つの事実
3. **Evidence**: 大きな証拠写真1点＋事実2–3点
4. **Detail Pair**: 主写真70%＋ディテール30%
5. **Specification**: 共通仕様を縦に3群、シリーズ差をタブではなく順送り

同一ページへ写真3枚、長文、仕様表を同時に置かない。

## 8. 写真のアートディレクション

### 原則

- CSSの`object-position:center`だけで最終調整しない。
- 各写真にPC/SP別の書き出しを用意する。
- 住宅写真は屋根、軒、玄関、開口部など識別点を先に決めてから切る。
- 人物写真は顔、手元、図面のうち主役を一つに決める。
- 設備写真は空間全体か製品ディテールかを混同しない。

### ファイル規則

```text
{scene}-{role}-pc-2560.avif
{scene}-{role}-pc-1920.webp
{scene}-{role}-sp-1080.avif
{scene}-{role}-sp-1080.webp
```

### HTML

- `<picture>`でPC/SPのアートディレクション画像を切り替える。
- `srcset`は解像度違い、`media`は構図違いに使う。
- `object-position`は微調整に限定し、主役救済の代わりにしない。
- 次の1面だけ先読みし、それ以降は遅延読み込みする。

### 焦点台帳

各画像に以下を記録する。

| 項目 | 内容 |
|---|---|
| 主役 | 必ず見せる対象 |
| 禁止クロップ | 切ってはいけない屋根、顔、手、玄関等 |
| PC焦点 | `x/y`百分率 |
| SP焦点 | `x/y`百分率 |
| 文字安全域 | 文字を重ねられる領域 |
| 出典 | 所有素材、パンフ頁、メーカー提供等 |
| 加工 | 色補正、背景拡張、生成有無 |

## 9. 画像生成・Adobe運用

### Higgsfield等を使う範囲

- SP表紙オープニングの中間背景
- 金線の出現、光の移動、和紙の呼吸
- 画面外へ続く背景の補助

禁止:

- 燕の最終形を生成させる
- 実邸、設備、構造、図面を作り替える
- ロゴ、日本語、仕様値を映像へ焼き込む

### Adobeを使う範囲

- Lightroom/Photoshop: 色温度、垂直、局所コントラスト、不要物の軽微な除去
- Generative Expand: 余白確保のみ。建物形状を変えない
- Adobe Stock: 和紙、箔、光、影、綴じ、紙端の補助

加工前原本、作業ファイル、Web書き出しを別保存する。生成・拡張を行った画像は台帳へ明記する。

## 10. SP表紙オープニング V3設計

現V2は9:16ファイルとしては独立しているが、V3ではSP専用の構図と時間設計を先に作る。

### 9:16キーフレーム

| 時間 | 表現 |
|---:|---|
| 0.00–0.60秒 | 深紅和紙と中央の空押し。タイトルは出さない |
| 0.60–2.50秒 | 上左・下右から金の牡丹線が静かに現れる |
| 0.90–3.90秒 | 上の燕は右から左、下の燕は左から右へ、中央安全域内だけを滑空 |
| 3.90–4.45秒 | 二羽が正本位置へ収束し、正本表紙へクロスフェード |
| 4.15–5.10秒 | 生きたHTMLの「花鳥風月」を表示 |
| 4.45–5.70秒 | 正本表紙を静止保持 |

### SP固有ルール

- 燕は左右端から欠けて入らない。最初から全身が画面内にある。
- 上下の燕を同じ高さへ重ねない。
- 中央45%はタイトル安全域として、飛行の交差を避ける。
- PCのカメラや軌道を切り抜いて使わない。
- 花、燕、タイトルを別レイヤーにする。
- 3枚の静止キーフレーム承認後にだけ動画生成・合成へ進む。

## 11. 文字組み

- 本文: 15–16px、行間1.8以上
- 仕様・注記: 14px未満にしない
- 見出し: 24–34px、2–4行以内
- 本文の1行: 19–25字程度
- 英字ラベル: 10–11px、補助情報に限定
- 明朝体は見出し中心。長文本文へ使わない
- 自動縮小で1面へ収めない。あふれたら編集か改ページを行う

## 12. 操作仕様

### ページ送り

- PC: 前へ／目次／次へ、左右キー、横スワイプ
- SP: 48×48px以上の前後ボタン、横スワイプ、目次ボトムシート
- 横スワイプ成立条件: `abs(dx) > 1.35 × abs(dy)` かつ45px以上
- 縦方向と判定したジェスチャーは奪わず、通常スクロールへ渡す

### スクロール

- 全ページ閲覧を強制しない。
- ホイール、トラックパッド、縦スワイプで次セクションへ進める。
- カタログ内でスクロールロックしない。
- 目次を開いている間だけ背景スクロールを止める。

### 表紙動画

- 初回だけ自動再生する。
- 「スキップ」を開始時から表示する。
- 一度完了したセッションでは、表紙へ戻っても自動再演しない。
- 再演は明示的な「もう一度見る」で行う。
- `prefers-reduced-motion`では最初から静止表紙を出す。

### 目次

- SPは画面下から70svh以内のボトムシートとして開く。
- 20面すべてを並べず、章単位10項目を表示する。
- 現在章、読了した章、未閲覧章を色ではなく記号とテキストでも区別する。

## 13. ページ送りの見た目

### PC

- 420ms前後
- 紙の影は一枚だけ
- 立体回転は最大6度相当
- 次面が前面へ覆いかぶさる大きなセクション演出にはしない

### SP

- 260–320ms
- 横移動16–24px＋クリップ＋薄い陰影
- 大きな3D回転やページカールを使わない
- 写真と文字を別々に遅延させない

`prefers-reduced-motion`では即時切替、または120ms以下のクロスフェードとする。

## 14. CTA設計

- 常設ヘッダー: 「来場予約」一つだけ
- 最終面の主CTA: 「モデルハウスを予約」
- 従CTA: 「資料を請求」
- 退場導線: 「サイト本編を見る」
- 途中面へ大きなCTAを重ねない
- CTAは写真の主役や本文を覆わない

## 15. アクセシビリティ

- 320px幅で情報欠落と横スクロールを発生させない
- 200%拡大で本文と操作を利用できる
- 操作ターゲットは原則48px、最低でも24px＋十分な間隔
- キーボードだけで前後移動、目次、終了ができる
- 現在ページは`aria-live="polite"`で通知する
- 装飾画像は空alt、証拠写真は内容を説明するaltを付ける
- 色だけでシリーズや状態を区別しない
- フォーカスを固定ヘッダーや操作列で隠さない

## 16. パフォーマンス予算

- SP表紙ポスター: 160KB以下を目標
- SP表紙動画: 3.8MB以下を上限目安
- SP主写真: AVIF 180KB以下、WebP 260KB以下を目標
- 初期表示で読むのは表紙＋次の1面まで
- 表示面の次1面だけ先読みする
- 非表示のPC/SP両画像を同時取得しない
- レイアウト幅・高さを事前指定し、切替時のガタつきを防ぐ

## 17. 計測

公開後に以下を記録できる設計にする。

- `catalog_open`
- `catalog_opening_skip`
- `catalog_page_view`（page_id、mode）
- `catalog_toc_open`
- `catalog_exit`（page_id、direction）
- `catalog_cta_click`（reserve、docs、main）

閲覧完了率だけを成功指標にしない。モデルハウス予約、資料請求、本編到達との関係を見る。

## 18. QA状態マトリクス

### 各幅で確認する状態

- 表紙0秒、2秒、終端
- 20面すべて
- 目次開閉
- 最初の面で「前へ」
- 最終面で「次へ」
- 横スワイプと縦スクロールの判定
- 低速回線時のポスター表示
- 動画失敗時
- reduced motion
- 200%拡大
- キーボード操作

### 画像合格条件

- 主役が3秒以内に特定できる
- 屋根、玄関、顔、手、図面などページの証拠が欠けていない
- 文字を読むためにピンチ拡大を要求しない
- 写真の重要部へ文字・操作UIが被らない
- 同じ写真の無意味な反復をしない

### 証跡

- PC/SP全ページのコンタクトシート
- SP20面の個別原寸スクリーンショット
- 表紙動画10フレーム比較
- 320 / 390 / 430 / 768 / 1024 / 1440 / 1920のレポート
- Safari系とChromium系の操作動画

## 19. 実装順序

1. 共通コンテンツマニフェストを作る
2. SP20面の低忠実度ワイヤーを作る
3. 各写真の焦点台帳を作る
4. SP専用クロップを全点書き出す
5. SP20面を静止状態で実装する
6. PC13面との共通操作を接続する
7. 目次、スワイプ、スクロール退場を実装する
8. SP表紙V3の3キーフレームを制作・承認する
9. 動画を制作・統合する
10. 全幅・全状態QAを行う
11. 承認後にcommit/pushする
